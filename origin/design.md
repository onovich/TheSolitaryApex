《孤崖》(The Solitary Apex) - 项目交接与设计文档

一、 项目概述

项目名称： 孤崖 (The Solitary Apex)

当前版本： V0.1 (Web前端核心玩法原型)

游戏类型： 2D 硬核生存 / 攀岩模拟 / 心理惊悚

核心体验： 模拟真实攀岩中的肢体控制、耐力（泵感）管理，以及濒临力竭时的心理压抑感。

技术栈： React + Vite + HTML5 Canvas + CSS。核心玩法逻辑保持在独立的 engine 模块中，Canvas 负责渲染，React 负责 HUD、弹窗、开发者调参面板与交互组织。

二、 项目启动方式

运行环境： 任何支持 HTML5 Canvas 和 ES6 语法的现代浏览器（Chrome, Edge, Firefox, Safari等）。支持 PC 端鼠标交互及移动端触摸交互。

启动步骤：

本项目目前为 Vite 前端应用。

本地开发：

```bash
npm install
npm run dev
```

玩法与构建回归：

```bash
npm run validate
npm run build
```

三、 需求与系统设计文档 (当前已实现)

目前原型已验证游戏的核心循环（Core Loop）：“观察点位 -> 肢体转移 -> 耐力消耗 -> 休息/打粉 -> 继续攀登”。

1. 核心机制

四肢独立控制： 角色由重心（COM）和四个肢体（左手、右手、左脚、右脚）组成。玩家通过拖拽圆环来移动肢体。

吸附与抓握： 拖拽肢体末端靠近岩点时，会自动进行距离判定。松手时，若在岩点吸附半径内且未超出躯干最大伸展距离（MAX_REACH），则抓握成功。

重心物理（伪物理）： 重心（COM）会动态计算已附着肢体的几何中心，并略微偏下，模拟重力下坠感。

2. 耐力（泵感 / Pump）系统

耐力是生存的唯一指标（满值 MAX_STAMINA = 100）。

支撑点消耗模型：

4点支撑：安全姿态，耐力缓慢恢复 (-0.1/帧)。

3点支撑：移动姿态，耐力基础流失 (+0.05/帧)。

2点支撑：危险姿态，耐力剧烈流失 (+0.4/帧)。

< 2点支撑：失去平衡，即刻坠落判定。

岩点质量惩罚： 抓握劣质岩点（Crimp/Sloper）会额外增加耐力流失速度。

坠落条件： 耐力归零，或附着点少于2个。

3. 道具系统

镁粉 (Chalk)： 初始携带3次。点击使用后，在 300 帧（约 5 秒）内大幅降低耐力流失速度，甚至在3点支撑时也能缓慢回体。

保护点 (Protection Cam)： 初始携带2次。处于足够稳定姿态时可设置保护点。冲坠后不会立刻 Game Over，而是进入保护绳坠落、悬挂、收绳和重新抓回路线的回收流程，同时扣减耐力上限作为惩罚。

能量胶 (Energy Gel)： 初始携带1次。仅能在单手悬挂且支撑条件成立时开始持续补给，完成读条后恢复大量耐力。

四、 交接文档 (代码架构与约束)

1. 全局状态管理

游戏的核心状态均存储在 state 对象中，方便后续重构为面向对象或引入状态机：

state.isPlaying: 游戏循环开关。

state.stamina: 当前耐力值。

state.inventory / state.activeEffects / state.itemState: 道具数量、限时效果、保护点和持续使用中的道具状态。

state.holds: 存储所有生成的岩点实例。

state.player: 包含四肢数组 limbs 和重心坐标 com。

2. 关键类与函数

class Hold: 岩点类。包含坐标、类型（0:好抓, 1:一般, 2:极差）和渲染方法。

class Limb: 肢体类。记录手/脚标识及当前绑定的 holdIndex。

generateWall(): 关卡生成器。当前已使用 Golden Path 主路径和路段分区生成，保证主路线可解，并在周围撒布干扰点与更高消耗的陷阱点。

updateFrame(): 核心逻辑层。处理坠落判定、保护绳回收、重心位置更新、拖拽逻辑、Dyno、天气、手伤和耐力计算。

GameCanvas/drawScene(): 核心渲染层。负责绘制背景、岩点、角色骨架连线、保护绳、Dyno 蓄力线和粒子特效。

五、 美术与视觉约束 (Art Guidelines)

为了保持类似《孤高之人》的硬核、极简、心理惊悚氛围，后续开发（即使引入图片美术）请遵循以下约束：

色彩调色板 (Color Palette)：

背景： 深邃的黑灰色为主（如 #050505），拒绝高亮背景。

交互元素： 灰白色调（#ddd, #fff）用于表示安全的肢体、优质岩点。

危险警告： 当体力见底时，使用强烈的红色（如 #e74c3c）和红色描边。

几何与线条 (Shapes & Lines)：

当前为线框风格（Wireframe）。如果替换为 Sprite/Spine 动画，要求角色肌肉线条紧绷，避免卡通Q版比例，采用写实比例。

视觉反馈与特效 (VFX)：

心跳与呼吸： 依赖代码驱动的缓动动画（目前为 Math.sin 驱动的重心膨胀），后续可加入手柄震动或屏幕微震。

心理恐惧 (幻觉)： id="vignette" 的 CSS 径向渐变层用于模拟缺氧时的隧道视觉（Tunnel Vision）。体力越低，边缘越黑，且伴随高频透明度闪烁。

六、 待进一步探讨与开发的 TODO (Roadmap)

此部分记录了早期的设计探讨，供后续开发节点参考和实现。

1. 路线生成与关卡配置 (Solvability / Level Config - 优先级：高)

当前状态： Golden Path 主路径、路线分区（恢复段、读线段、风口段、卡点段）和干扰点已经落地，原先“纯随机导致死局断层”的风险已被第一版解决。

下一步重点不是继续堆随机，而是定义“哪些内容由配置控制，哪些内容允许随机”：

需要配置控制的内容： 每段长度范围、路段顺序、岩点类型池、风压倍率、耐力修正、道具投放规则、特殊事件触发高度、关卡目标与失败惩罚。

适合随机的内容： 同一配置范围内的岩点横向偏移、少量噪声点数量、风压相位、粒子表现、可替代路线的局部扰动。

不适合纯随机的内容： 主路线可达性、关键资源是否必经、危险机制首次出现时机、连续高压段长度、玩家是否能在教学期理解新规则。

当前配置方案： 关卡节奏与路线生成参数集中在 `src/data/levelConfig.js` 的 `LEVEL_CONFIGS` 中维护。每个 level 声明 `wallHeight`、`routeGeneration`、`zoneSequence` 和分区模板；每个分区模板包含目标体验、岩点类型池、干扰点数量、风压/耐力修正，以及未来脆弱点、软体点、障碍、资源点的 `mechanicBudget` 投放位。

配置工具： `npm run validate:levels` 会校验关卡 ID、范围参数、岩点类型池、路段引用，并真实生成一条路线验证分区覆盖与 Golden Path 可解性。以后改关卡配置时，应先跑此命令，再跑完整 `npm run validate`。

复现工具： 每个关卡配置包含稳定 `seed`。路线生成会用 `level id + seed + viewport` 生成可复现的随机序列；`validate:levels` 会重复生成并比对路线签名，确保调参时可以固定同一条路线观察差异。

建议演进： 在当前 `LEVEL_CONFIGS` 基础上继续扩展可组合的关卡段模板。每个模板声明“目标体验、生成约束、可投放机制、禁止机制、强制验证项”，生成完成后继续跑 solvability / stamina / event-density 检查。

2. 仿真道具与战前准备 (Item / Loadout - 优先级：中)

保护点 (快挂/机械塞 Quickdraws/Cams)： * 引入存档点机制。当处于安全姿态且遇到特定裂缝时，可消耗道具设置保护点。冲坠时不会直接 Game Over，而是掉落至最近的保护点（扣除大量生命值/永久耐力上限以示惩罚）。

攀岩鞋 (Climbing Shoes)： * 战前装备策略。例如：平底鞋耐力消耗低，但在劣质岩点易滑脱；重度下弯鞋抓劣质岩点极稳，但由于挤脚，每攀爬一定高度会扣减体力上限。

能量胶 (Energy Gel)： * 瞬间恢复大量耐力。但使用条件苛刻：必须在单手悬挂时操作，且操作需要持续耗时（期间耐力照常流失）。

当前状态： 保护点、保护绳冲坠回收、能量胶单手持续补给已经实现。攀岩鞋尚未实现，是否值得做取决于它能否改变路线阅读，而不是只做成数值皮肤。

战前准备策略建议： 不做复杂装备 RPG，先做“少量明确取舍”。例如每局开始前从 2-3 个 loadout 中选一个：稳健型（更多镁粉/低惩罚）、冒险型（更强 Dyno/更少保护）、技术型（劣质点更稳/恢复更慢）。这样能增加重复游玩差异，但不会把核心从攀爬判断拖向配装菜单。

当前实现： 已加入三套 loadout，配置集中在 `src/data/loadoutConfig.js`。稳健型提供更多镁粉和保护点但 Dyno 略重；冒险型减少保护、强化 Dyno；技术型减少补给资源，降低劣质岩点耐力惩罚。HUD 顶部可切换，切换后以对应战前配置重新开始。

攀岩鞋建议： 暂列为低风险原型项。只有当关卡开始明显区分摩擦点、尖点、脚点和动态移动时，鞋子的抓点差异才有意义；在当前抽象岩点系统下，可以先不做，避免增加看不见的复杂度。

3. 进阶动作与环境扩展 (Gameplay Extensions - 优先级：中/低)

动态腾跃 (Dyno)： 允许按住重心（COM）向下蓄力，像弹弓一样将角色弹射出去抓取极远处的岩点。高风险高回报机制。

当前实现备注： 现已落地为“先打保护点，再长按身体并反向拖拽进行弹射”的版本，并在最高点进行自动吸附判定。

后续优化待办：

优先调手感参数： 长按触发阈值、反拉距离区间、弹射速度三组参数应继续微调，以提升蓄势反馈和起跳强度的一致性。

优先优化自动吸附策略： 最高点检索应进一步偏向上方岩点，并避免多个肢体在同一次弹射结算中抢占同一个最佳点位。

开发者调参： 当前 Web 版已加入 `DEV` 面板，可在运行时调整 Dyno 的蓄力帧、反拉距离、弹射速度、触及奖励、重力、冷却和耐力成本。`Save local` 保存到浏览器本地，`Copy config` 导出可回填到 `src/data/gameConfig.js` 的正式数值片段。

特殊休息姿态 (Resting Poses)： 判定逻辑扩展。如果检测到左右脚处于水平对峙状态（模拟挂脚/膝盖卡死），可触发“完美休息”状态，双手脱离也能快速回体。

动态天气系统 (Weather Effects)： * 高空狂风： 施加横向持续的力，考验玩家的防风抓握策略。风压应具备明确风向，并在可视化中通过粒子动画表达，让玩家能提前判断受力方向。

风压摆动反馈： 保护绳和玩家肢体都可受到风压影响，沿风向发生轻微摇摆。其中保护绳摆幅更大，玩家肢体摆幅更小，用于强化高空受风的临场感与风险提示。

饥渴值与可采集果子： 可追加独立于耐力之外的生存压力。玩家在攀爬途中可获取果子补充饥渴值；果子的外形与普通攀爬点接近，但尺寸更小且带有明显颜色，要求玩家在读线时区分“可抓握资源”和“可消耗资源”。

当前实现： 已作为轻量生存压力接入。饥渴值随时间缓慢上升，超过阈值后压低耐力收益；果子作为不可抓取资源点出现在干扰点中，拖拽肢体靠近即可采集，采集后降低饥渴并恢复少量耐力。`mechanicBudget.resource` 控制投放概率，`mechanicRules.resourceFruit` 控制采集半径、果子尺寸、耐力恢复和饥渴缓解值。

背景流动光效与五感激活： 为缓解长时间攀爬的单调感，可在背景中加入极淡的流动光效来优化整体体验，但透明度必须保持较低，避免喧宾夺主、干扰读点与肢体判断。该效果可在特定时刻短暂增强，例如食用特殊果子后进入“五感激活”状态，以形成明确的感官峰值反馈。

当前实现： 已加入果子触发的轻量 sensory-flow 叠层。默认透明度为 0，仅在采集果子后短暂淡入，使用低对比流动纹理表达“五感激活”，不影响岩点、障碍和肢体判读。

延迟脱落岩点： 增加一类颜色更暗的脆弱攀爬点。玩家抓上去时不会立刻掉落，但在下一次离开该点后，它会随之脱落，改变回撤路线与后续站位。

当前实现： 已作为干扰点风险机制接入。`levelConfig` 中的 `mechanicBudget.fragile` 控制各路段投放概率；脆弱点不会投放到 Golden Path，因此不会破坏主路线可解性。玩家离开该点后岩点碎落并从可抓取候选中移除。

计时脱落的软体岩点： 作为上一类脆弱岩点的进阶版，配色接近但轮廓更不规则，呈现某种软体或塌陷感。玩家攀附后经过数秒便会自行掉落，迫使玩家快速完成转移。

当前实现： 已作为干扰点风险机制接入。`levelConfig` 中的 `mechanicBudget.timedSoft` 控制各路段投放概率，`mechanicRules.timedSoft` 控制崩塌帧范围。玩家攀附后开始计时，倒计时结束时岩点塌落、对应肢体强制脱手；若因此低于 2 个支撑点，则进入坠落判定。

可钻除的障碍石块： 增加一种名为“障碍物”的石块，外观上类似攀爬点，但更有棱角，可呈现四边形到六边形等不同轮廓，且尺寸有明显差异。玩家获得钻头能力后，可将肢体端点拖到石块附近并长按持续钻除小型石块，过程中持续消耗耐力，并让相机产生轻微高频震动；石块被钻碎时，需要有小碎片粒子动画反馈。较大的石块默认无法钻除，后续可通过能力升级解锁更高钻除上限，但仍保留一部分超大尺寸障碍石块作为始终不可破坏的地形阻挡。

当前实现： 已作为不可抓取的干扰点机制接入。`mechanicBudget.obstacle` 控制投放概率，`mechanicRules.obstacle` 控制钻除所需帧数、触发半径、耐力消耗和尺寸范围。玩家拖拽肢体靠近障碍并持续停留即可钻碎；障碍本身不会进入可抓取候选，因此不会伪装成合法支点。

岩点流血/污染： 多次抓握尖锐岩点导致手指破皮，带有血迹的岩点摩擦力剧减，必须使用创可贴或消耗额外镁粉处理。

UGC 路线编辑器： 允许玩家自定义放置岩点，设定通关条件，提供类似《马里奥制造》的玩家社区内容闭环。

当前判断： UGC 路线编辑器暂不作为近期目标。它会引入编辑器 UI、关卡校验、分享格式、审核与社区闭环，而当前原型最缺的是核心机制密度和关卡配置语言。更靠谱的中间态是先做“开发者路线配置/种子复现/调参验证”，等官方关卡生成稳定后再评估是否开放给玩家。

4. 遭遇设计与特殊事件扩展 (Encounter & Scenario Extensions - 优先级：中/低)

同类协作桥段： 后续在山上可加入其他攀爬者。可设计为把保护点打在对方身上，再接力将对方拉上来的互助段落，用于放大“保护点”从自保工具到协作工具的玩法价值。

伤员救援桥段： 某些 NPC 已经受伤、无力自主攀爬，玩家需要把保护点打在对方身上并持续将其拉起。对方会长时间垂挂，持续增加额外重量与耐力压力；随着剧情推进，NPC 可逐步恢复行动力，减轻负担。

被敌人追赶： 设计持续逼迫玩家移动的追赶型事件，让读线、体力管理与风险决策在高压下同时发生。

当前实现： 已加入第一版“追赶压力线”原型，暂不引入敌人 AI。`levelConfig.pursuit` 控制触发帧、上升速度、危险距离和额外耐力压力；追赶线从下方逼近，进入危险距离后 HUD 高亮并增加耐力压力，用于验证高压读线节奏。

地震与雪崩： 作为环境级特殊事件，短时间改变岩点稳定性、可通行路线或站位安全性，迫使玩家临时改变攀爬方案。

当前实现： 已加入配置驱动的地震事件原型。`levelConfig.environmentEvents` 定义触发帧、持续时间和影响数量；事件触发时只会把普通干扰点转化为脆弱点，并显示环境状态和轻微画面震动，不会直接改动 Golden Path。

山道封锁型敌人： 部分敌人不主动长距离追击，而是卡在特定山道或狭窄路径上。玩家若进入其攻击圈就会受袭，需要提前观察并选择绕道。

地形利用与诱敌： 较高阶的对抗方向，可尝试让玩家将敌人引诱到难以返回的位置，甚至利用地形或坠落机制让对方失足。此项需要先验证 AI 行为边界与反馈清晰度是否足够支撑公平感。

沿保护绳追击的小型敌人： 某些体型较小的敌人可顺着玩家布设的保护绳向上攀爬，反过来把保护系统转化为新的威胁来源。

破坏保护点的敌人： 让部分敌人具备摧毁保护点的能力，迫使玩家重新规划布点节奏，并提高临时安全区的不确定性。

空间旋转与伪 3D 关系： 可尝试给每个攀爬点记录 z 轴信息，但实际抓取与碰撞仍按 2D 投影处理。当当前空间关系不利于攀爬时，允许玩家旋转整个场景，改变前后层关系，把原本不利的路线转化为可用解法。

当前判断： 伪 3D 旋转是高影响机制，不能直接并入主线。它会改变读线节奏、岩点可见性、失败责任归因、相机表达和关卡生成约束。正式实现前应先做独立小原型，只验证三个问题：玩家是否能预判旋转收益；旋转是否让路线阅读变丰富而不是变混乱；它是否与四肢拖拽节奏兼容。若验证不通过，保留为特殊关卡事件，而不是基础能力。

当前实现： 已加入默认关闭的“空间扫描”实验。关卡生成会为岩点记录 `zLayer`，`levelConfig.routeGeneration.spatialExperiment` 控制最大扫描角与投影强度。HUD 中的“空间”控件只改变画面投影，不改变抓取、碰撞、Golden Path 可解性或物理判定，用于先验证旋转是否能提升读线而不是扰乱核心操作。
